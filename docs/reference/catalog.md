### DELETE `/IDMProv/rest/access/assignments`

Removes the signed-in user's own role/resource/PRD permission assignments (self-revoke).

**Status:** validated on the lab. **Evidence:** server code + live 2026-10-31.

| Body field | Required | Accepted values | Kind |
|---|---|---|---|
| `assignments` | yes | non-empty list, else 489 'permission required' |  |
| `assignments[].id` | yes | role or resource DN | per installation |
| `assignments[].entityType` | yes | role, resource or prd | fixed |
| `assignments[].instanceId` | no | required for resources: the assignment instance GUID from the user's assignment list | per installation |
| `reason` | no | request description |  |
| `correlationId` | no | generated when absent |  |

```json
{
  "reason": "no longer needed",
  "assignments": [
    {
      "id": "cn=Helpdesk-Group,cn=System,cn=ResourceDefs,cn=RoleConfig,cn=AppConfig,cn=User Application Driver,cn=driverset1,o=system",
      "entityType": "resource",
      "instanceId": "<instance guid>"
    }
  ]
}
```

**Answer:** {success, succeeded:[{id}]}

**Example:** DELETE …/access/assignments {reason, assignments:[{id, entityType, instanceId}]}

**Notes:** Removed a role the caller held directly (entityType role, no instanceId needed); GET /access/assignments no longer listed it 20 s later. Acts on the caller's own assignments only. Inherited assignments and non-removable ones are refused with their own messages. Errors seen on the lab: an empty assignments list → 489 'No permission assignment(s) were specified for removal'.

### GET `/IDMProv/rest/admin/administrator/assignments`

Lists the administrator assignments (domain and delegated admins) in all domains.

**Status:** validated on the lab. **Evidence:** server code + live 2026-10-30, live 2026-10-31.

| Parameter | In | Required | Accepted values | Kind |
|---|---|---|---|---|
| `q` | query | no | search on the assignee name; * or empty means all (default *) |  |
| `sortColumn` | query | no | column key from …/assignments/columns, e.g. assignee, domain, adminType (default assignee) | fixed |
| `sortOrder` | query | no | asc or desc (default asc) | fixed |
| `nextIndex` | query | no | 1-based start (default 1) |  |
| `size` | query | no | page size (default 20) |  |
| `filterSearch` | query | no | filter handed to the assignment reader (default ALL); an unknown value was ignored on the lab |  |

**Answer:** {adminAssignments:[{assignee, assigneeDn, assignmentType, assignmentTypeKey, adminType, adminTypeKey, comment, domain, domainType, effectiveDate, status}], nextIndex, totalSize, total}

**Example:** GET …/admin/administrator/assignments?q=*&nextIndex=1&size=5&sortColumn=assignee&sortOrder=asc

**Notes:** Lab: uaadmin holds both Domain Admin and Delegated Admin rows for Provisioning, etc. Values seen: adminTypeKey DOMAIN_ADMIN / DELEGATED_ADMIN, assignmentTypeKey USER, domainType PROVISIONING/ROLES/RESOURCES/SECURITY, status COMPLETED. Dates are epoch milliseconds. filterSearch=bogus gave the same rows as ALL. The end of the list is marked nextIndex -1 (other lists use 0). A delegated administrator made with …/assignments/create shows with status COMPLETED at once.

Makes an identity a domain administrator or delegated administrator of a domain.

**Status:** validated on the lab. **Evidence:** server code + live 2026-10-31.

|---|---|---|---|
