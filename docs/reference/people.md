### GET `/IDMProv/rest/access/codeMap/{id}/values`

Lists the values of one entitlement code map, paged and filtered.

**Status:** answered on the lab, which had no data to show. **Evidence:** server code + live 2026-10-30.

| Parameter | In | Required | Accepted values | Kind |
|---|---|---|---|---|
| `id` | path | yes | code map id, Base64-encoded (the server decodes it before the lookup) | per installation |
| `q` | query | no | '*' returns all values; a value starting or ending with '*' is used as given; anything else is searched as *value*. Default 'default' (so it searches *default*) |  |
| `nextIndex` | query | no | 1-based start, default 1 |  |
| `size` | query | no | page size, default 10 |  |

**Answer:** {nextIndex:int, arraySize:int, hasMore:bool, codeMapValues?:[...]}

**Example:** GET …/codeMap/SGVscGRlc2sgRW50aXRsZW1lbnQ=/values?q=*&nextIndex=1&size=5

**Notes:** An unknown id is not an error: it answers 200 with arraySize 0. The lab has no entitlement code maps (no drivers with entitlements in the catalog), so every id tried came back empty. A blank id gives 489. The dashboard reads codeMapValues from the answer.

### POST `/IDMProv/rest/access/containers/container`

Lists the first-level sub-containers under a root (a read despite POST).

**Status:** validated on the lab. **Evidence:** server code + live 2026-10-30.

| Body field | Required | Accepted values | Kind |
|---|---|---|---|
| `dn` | no | container to list under; wins over everything else | per installation |
| `level` | no | role level number; lists under that level's container; with level 20 the 'System' sub-container is left out | per installation |
| `type` | no | only 'resource' (any case) is checked: lists resource-definition containers under the resource root | fixed |
| `searchScope` | no | 'o'/'one' (one level, the default) or 's'/'subtree'; anything else is 489 | fixed |
| `name` | no | ignored |  |

```json
{
  "dn": "cn=RoleDefs,cn=RoleConfig,cn=AppConfig,cn=User Application Driver,cn=driverset1,o=system"
}
```

**Answer:** {dn:str, name:str, subContainers:[{dn,name}], arraySize:int}

**Example:** POST …/containers/container {} → o=data with devices, groups, sa, users

**Notes:** An empty body lists under the user entity's search root (lab: o=data). The dashboard sends {} (users), {id:'',type:'resource'} (resources) and {dn:<role root>} (roles). type 'role' or 'prd' is not special and falls back to the user root. Values are XSS-checked (400).

### GET `/IDMProv/rest/access/counts`

Counts roles, resources or users (one kind per call).

**Status:** validated on the lab. **Evidence:** server code + live 2026-10-30.

| Parameter | In | Required | Accepted values | Kind |
|---|---|---|---|---|
| `roles` | query | no | 'true' to count roles | fixed |
| `resources` | query | no | 'true' to count resources | fixed |
| `users` | query | no | 'true' to count users | fixed |
| `clientId` | query | no | dashboard client configuration id; defaults to 1 (lab: 1) | per installation |

**Answer:** {usersCount:int, rolesCount:int, resourcesCount:int, hasMore:bool} (uncounted kinds are -1)

**Example:** GET …/counts?users=true&clientId=1

**Notes:** Only one kind is counted even when several flags are true: roles first, then resources, then users. With all flags false the server raises 'Please choose entities to get the count', which reaches the client as a 500 HTML error page. Users are counted in the client's users-list container and capped (hasMore true when the cap is hit) unless VLV counting is on. The lab answered 0 for roles and resources although system roles exist. Dashboard sends users=true&clientId=<client>.

<a id="get-idmprov-rest-access-entities-list"></a>
### GET `/IDMProv/rest/access/entities/list`

Searches objects of one DAL entity, paged, or reads one object by DN.

**Status:** validated on the lab. **Evidence:** live 2026-10-30 (test users, groups and a team).

| Parameter | In | Required | Accepted values | Kind |
|---|---|---|---|---|
| `entityKey` | query | yes | entity definition key; required | per installation |
| `q` | query | no | search string, default empty (dashboard sends *) |  |
| `searchKeys` | query | no | comma-separated attribute keys to search and show; needed when the client has no entity configuration for this key | per installation |
| `filterAttr` | query | no | comma-separated attribute keys to return | per installation |
| `entityDN` | query | no | returns just that object (with filterAttr attributes) |  |
| `isDynamic` | query | no | 'true' searches with the definition's searchable attributes when no configuration exists; default false | fixed |
| `isOrgChart` | query | no | 'true' uses the org-chart display attributes; default false | fixed |
| `lookupAttr` | query | no | 'true' also returns lookup attributes; default false | fixed |
| `advSearch` | query | no | ';'-separated key:value terms (e.g. FirstName:a*;LastName:b*); keys must be searchable, non-time attributes | per installation |
| `sortBy` | query | no | attribute key; must be one of the entity's display attributes | per installation |
| `sortOrder` | query | no | asc (default) or desc | fixed |
| `nextIndex` | query | no | 1-based start, default 1 |  |
| `size` | query | no | page size, default 20 |  |
| `clientId` | query | no | dashboard client configuration id; defaults to 1 (lab: 1) | per installation |

**Answer:** {entityList:[{dn, attributes:[{key, displayLabel, attributeValues:[…], dataType, …}]}], nextIndex (-1 = no more), totalCount, hasMore}; with entityDN+filterAttr: {entityList:[{dn, attributes:[{key, attributeValues:[{@type:'entityInfoNode', dn, name, type}]}]}]}

**Example:** GET …/access/entities/list?entityKey=user&q=*&searchKeys=FirstName&nextIndex=1&size=2

**Notes:** With searchKeys the rows carry only those attributes; with isDynamic=true all the entity's display attributes (Department, Email, FirstName, …). Paging: size=2 gave nextIndex 3, totalCount 3. entityDN + filterAttr reads DN-valued attributes of one object, resolved to names: filterAttr=directReports on the manager listed both reports; filterAttr=manager,group on Alice gave her manager and her group (comma-separated keys work). entityKey=group with searchKeys=Description listed both groups; searchKeys=cn for groups gave 489 'Internal Error' (use an attribute the definition has; cn is not one for group). sortBy FirstName or LastName: 489 'Sort column is not specified as entity display attribute' (no per-client entity configuration on the lab, so no display attributes to sort by). With no per-client entity configuration (dashboard Configuration > Entities) and neither searchKeys nor isDynamic, the server answers 489 'Entity configuration is missing'. sys-nrf-role with searchKeys=cn also gave 'Internal Error'.
